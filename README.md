# GREEN-API Telegram Chat

Тестовое задание Frontend React: простой клиент для отправки и получения текстовых сообщений Telegram через GREEN-API. Интерфейс с боковым списком чатов, историей, входящими и исходящими сообщениями и мобильным экраном разговора.

Выбран **Telegram**, поскольку условия тестового задания разрешают Telegram или WhatsApp, если использовать MAX не получается. Приложение работает с личным Telegram-аккаунтом через инстанс GREEN-API, а не через Telegram Bot API.

## Запуск

Требуются Node.js 22.13+ из ветки 22 LTS либо Node.js 24+, npm, авторизованный Telegram-инстанс GREEN-API и доступ к интернету.

```sh
npm install
npm run dev
```

Откройте адрес, показанный Vite (обычно http://127.0.0.1:5173).

```sh
npm run lint
npm test
npm run build
npm run preview
```

Дополнительно: `npm run test:e2e` запускает браузерные сценарии Playwright с подставными ответами API на десктопной и мобильной ширине. Для них нужен установленный Microsoft Edge; настоящий аккаунт не используется. `npm run format` форматирует исходники Prettier.

Сборка создаётся в `dist`. Backend и база данных не требуются.

## Подключение GREEN-API

1. Создайте инстанс **Telegram** в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте его, следуя [официальной инструкции](https://green-api.com/telegram/docs/before-start/). Рекомендуется QR: Telegram → Настройки → Устройства → Подключить устройство. Документация также допускает вход по коду и паролю двухэтапной аутентификации. Отключать пароль не требуется; авторизация выполняется вне приложения.
2. В параметрах доступа скопируйте `apiUrl`, `idInstance` и `apiTokenInstance`.
3. Для [получения через HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/) оставьте `webhookUrl` пустым и включите настройку **«Получать уведомления о входящих сообщениях и файлах»** (`incomingWebhook: yes`). После изменения настроек дайте сервису время применить их.
4. Введите три параметра в приложении. Приложение само настройки инстанса не меняет.

Почему три параметра: `apiUrl` указывает хост конкретного инстанса, `idInstance` выбирает инстанс, `apiTokenInstance` даёт доступ к API. Хост не вычисляется из ID и не подставляется по умолчанию. Завершающие `/` удаляются. Разрешены HTTPS-хосты `api.green-api.com` и числовые поддомены вида `<кластер>.api.green-api.com` без пути метода. Это не позволяет случайно отправить токен на посторонний сайт. Префикс версии в Telegram-запросы не добавляется.

Credentials вводятся пользователем и хранятся только в памяти приложения, как и история сессии. LocalStorage, sessionStorage, cookies и файлы для них не используются. «Изменить подключение» завершает сессию и возвращает пустую форму. Обновление страницы тоже очищает данные. Приложение не выводит токен в сообщения об ошибках или console. Токен, как требует API, передаётся в URL запроса: его можно увидеть в сетевой панели DevTools. Не пересылайте сетевые логи с реальными credentials.

Если `incomingWebhook` выключен, новые сообщения не поступают в очередь, и при пустой очереди `ReceiveNotification` возвращает `null`. Сам по себе `null` не означает ошибку: такой же ответ приходит при отсутствии новых уведомлений. Успешная отправка сообщения не подтверждает, что получение настроено.

## Реальная проверка

Приложение проверено пользователем с реальным GREEN-API Telegram instance. Подтверждены подключение с тремя параметрами, поиск получателя через CheckAccount, фактическая доставка SendMessage в Telegram и отображение ответа через ReceiveNotification.

В полученном уведомлении подтверждены `incomingMessageReceived`, `instanceData.typeInstance: telegram`, `senderData.chatId`, `messageData.typeMessage: textMessage` и `messageData.textMessageData.textMessage`. Реальные credentials, адресаты, идентификаторы и payload в проект не включены. Автоматические unit/e2e-тесты используют только синтетические данные и подставные ответы API.

## Использование

Введите международный телефон с кодом страны или `@username`. Для телефона удаляются пробелы, скобки и дефисы. Базовая клиентская проверка допускает 7–15 цифр без начального нуля; наличие Telegram проверяет сервер. Ограничения по РФ/РБ нет, код страны не изменяется: местный префикс `8` нужно самостоятельно заменить на международный код. Username приводится к нижнему регистру; ссылки `t.me` не принимаются.

По кнопке «+» вызывается `CheckAccount` с одним из полей: `phoneNumber` (число) или `username` (строка с `@`). Приложение использует возвращённый сервером `chatId`, не строит его из номера или username. Идентификаторы хранятся строками. Повторное открытие последнего использованного адреса чата не требует поиска. Если другой адрес разрешился в тот же `chatId`, сохраняется один чат с прежней историей. Можно также выбрать чат, автоматически появившийся после входящего текста.

Введите текст и нажмите кнопку отправки или Enter. Shift+Enter добавляет строку. Ограничение — 4096 символов. Пустые сообщения не отправляются. При ошибке текст сохраняется в текущем окне; автоматических повторов отправки нет. Если запрос оборвался, проверьте Telegram перед повторной отправкой: сервер мог принять сообщение.

Входящие тексты маршрутизируются по `senderData.chatId`. Для неизвестного чата появляется строка в списке. История прокручивается к последнему сообщению. На небольшом экране список и разговор показываются по отдельности.

## API и получение сообщений

Префикс всех запросов: `{apiUrl}/waInstance{idInstance}`.

| Метод  | Путь                                                        | Данные                                                          |
| ------ | ----------------------------------------------------------- | --------------------------------------------------------------- |
| POST   | `/checkAccount/{apiTokenInstance}`                          | `{ phoneNumber: number }` или `{ username: string }` → `chatId` |
| POST   | `/sendMessage/{apiTokenInstance}`                           | `{ chatId, message }` → `idMessage`                             |
| GET    | `/receiveNotification/{apiTokenInstance}?receiveTimeout=30` | `null` либо `{ receiptId, body }`                               |
| DELETE | `/deleteNotification/{apiTokenInstance}/{receiptId}`        | Подтверждение обработанного уведомления                         |

Один последовательный цикл выполняет receive → обработка → delete. Следующий запрос начинается после завершения предыдущего. Для разработки учитывается повторный запуск effect в React StrictMode. При выходе отменяются запросы и таймеры. У запросов есть локальный таймаут 45 секунд.

Временные ошибки повторяются с задержкой от 1 до 30 секунд. Ошибки HTTP 400/401/403 останавливают цикл до нового подключения. После пустого ответа есть небольшая пауза, чтобы исключить tight loop. Повторное получение уже обработанного сообщения не дублирует его в истории: используется ID сообщения в рамках чата и направления.

Принимаются `incomingMessageReceived` с `instanceData.typeInstance: "telegram"` и типом `textMessage` или `extendedTextMessage`. Текст извлекается из `textMessageData.textMessage` или `extendedTextMessageData.text`. Исходящие webhook-события, статусы, другие мессенджеры и нетекстовые события не отображаются, но подтверждаются, чтобы не блокировать очередь. Отправленные в приложении сообщения добавляются после ответа SendMessage. Timestamp входящих сообщений переводится из секунд в миллисекунды. Разметка входящего текста не выполняется как HTML.

Источники: [формат запросов](https://green-api.com/telegram/docs/request-format/), [CheckAccount](https://green-api.com/telegram/docs/api/service/CheckAccount/), [chatId](https://green-api.com/telegram/docs/api/chat-id/), [SendMessage](https://green-api.com/telegram/docs/api/sending/SendMessage/), [ReceiveNotification](https://green-api.com/telegram/docs/api/receiving/technology-http-api/ReceiveNotification/), [DeleteNotification](https://green-api.com/telegram/docs/api/receiving/technology-http-api/DeleteNotification/), [текстовые уведомления](https://green-api.com/telegram/docs/api/receiving/notifications-format/incoming-message/TextMessage/).

## Структура и стек

React, TypeScript strict, Vite, обычный CSS, ESLint. Vitest, Playwright и Prettier используются только для разработки. Глобального state manager и UI-библиотеки нет.

```text
src/
  api/          HTTP-клиент, разбор уведомлений, цикл polling, тесты
  components/   подключение, список чатов, новый чат, разговор
  hooks/        состояние сессии и жизненный цикл запросов
  utils/        проверка URL и нормализация телефона
  types.ts      модели credentials, чата и сообщения
  styles.css    интерфейс и адаптивная раскладка
```

## Ограничения и ручная проверка

- Это клиент текущей сессии: после обновления страницы подтверждённые уведомления не восстанавливаются. Черновик при переключении чатов не сохраняется.
- Используйте один клиент на очередь инстанса: другая вкладка, интеграция или webhook могут забрать уведомления раньше приложения.
- SendMessage подтверждает постановку в очередь, а не доставку. В интерфейсе это явно указано. Статусы доставки и сообщения, отправленные из других клиентов, не синхронизируются.
- Поиск зависит от приватности и лимитов Telegram. Если телефон скрыт, попробуйте публичный `@username`. При HTTP 469 срок ограничения неизвестен; не запускайте массовые проверки и попробуйте через несколько часов. Наличие чата не гарантирует право отправки в него.
- Прямые браузерные запросы зависят от CORS на хосте GREEN-API. Прокси не добавлялся; обходить ограничения браузера не нужно.
- Авторизация проверяется первым запросом получения, а не отдельным методом входа. Серверные настройки уведомлений меняются вручную в кабинете.
- Не реализованы файлы, звонки, реакции, редактирование, управление группами и загрузка старой истории.

С реальным инстансом проверьте подключение к вашему apiUrl (в том числе с завершающим `/`), создание чата по международному телефону и по @username, отправку, ответ из Telegram и правильное распределение ответов между двумя чатами. Затем проверьте неверный токен, отключение сети и восстановление, выход во время запроса, Enter/Shift+Enter и мобильную ширину. Не запускайте параллельно другой потребитель той же очереди.
